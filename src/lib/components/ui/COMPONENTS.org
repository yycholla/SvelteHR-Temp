* Overview
This document provides a comprehensive reference of all UI components available in our SvelteHR project, including both our custom-built components and Skeleton Labs components.

* Our Custom UI Components
Located in =src/lib/components/ui/=

** Layout & Structure Components

*** Card
- *Purpose*: Container component with structured layout
- *Variants*: default, outline, ghost
- *Sub-components*: CardHeader, CardTitle, CardDescription, CardContent, CardFooter
- *Import*: ~import { Card, CardHeader, CardContent } from "$lib/components/ui/card";~
- *Usage*:
  #+begin_src svelte
  <Card variant="default">
    <CardHeader>
      <CardTitle>Title</CardTitle>
    </CardHeader>
    <CardContent>Content here</CardContent>
  </Card>
  #+end_src

*** Separator
- *Purpose*: Visual divider component
- *Variants*: horizontal, vertical
- *Import*: ~import { Separator } from "$lib/components/ui/separator";~
- *Usage*: ~<Separator orientation="horizontal" />~

*** Skeleton
- *Purpose*: Loading placeholder components
- *Variants*: default, text, avatar, button, card
- *Import*: ~import { Skeleton } from "$lib/components/ui/skeleton";~
- *Usage*: ~<Skeleton variant="text" class="h-4 w-full" />~

** Form Components

*** Button
- *Purpose*: Clickable button with multiple styles
- *Variants*: default, destructive, outline, secondary, ghost, link
- *Sizes*: sm, default, lg, icon
- *Import*: ~import { Button } from "$lib/components/ui/button";~
- *Usage*: ~<Button variant="default" size="lg">Click me</Button>~

*** Input
- *Purpose*: Text input field
- *Types*: All HTML input types supported
- *Import*: ~import { Input } from "$lib/components/ui/input";~
- *Usage*: ~<Input type="email" placeholder="Enter email" bind:value={email} />~

*** Textarea
- *Purpose*: Multi-line text input
- *Sizes*: sm, default, lg
- *Import*: ~import { Textarea } from "$lib/components/ui/textarea";~
- *Usage*: ~<Textarea placeholder="Enter message" bind:value={message} />~

*** Label
- *Purpose*: Form field labels with accessibility
- *Import*: ~import { Label } from "$lib/components/ui/label";~

*** Checkbox
- *Purpose*: Checkbox input with checked state
- *Sizes*: sm, default, lg
- *Import*: ~import { Checkbox } from "$lib/components/ui/checkbox";~

* Integration Notes

** Component Priority
When both our custom components and Skeleton components exist for the same purpose:
1. Use our custom components for consistent styling with bits-ui
2. Use Skeleton components for advanced functionality not available in our set
3. Be mindful of naming conflicts (e.g., both have Switch, Tabs, Progress, Avatar)

** Theme Integration
- All components use the same Tailwind CSS variables defined in =app.css=
- Dark mode support is automatic for both component sets
- Custom CSS properties ensure consistent theming

** Accessibility
- Our components: Built on bits-ui primitives for maximum accessibility
- Skeleton components: Powered by Zag.js for cross-framework accessibility standards

** TypeScript Support
- Import types from individual component files
- Both component libraries provide full TypeScript support
- Use specific imports to avoid type conflicts

* Best Practices

** Component Selection
1. Prefer our custom components for standard UI needs
2. Use Skeleton components for specialized functionality (FileUpload, Slider, Pagination)
3. Avoid mixing similar components from both libraries in the same view

** Import Strategy
#+begin_src svelte
// Specific imports to avoid conflicts
import { Button } from "$lib/components/ui/button";           // Our custom
import { Slider } from '@skeletonlabs/skeleton-svelte';       // Skeleton
#+end_src

** Styling Consistency
- Both component sets respect the same CSS custom properties
- Use consistent variant names when available
- Apply additional Tailwind classes for customization
