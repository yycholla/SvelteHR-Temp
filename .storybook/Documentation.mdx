
## 🔌 GraphQL Operations

All GraphQL operations are implemented server-side only. Never call these operations from client-side components.

### Event Operations (`src/lib/graphql/events-operations.ts`)

**Queries**:
- `getAllEvents` - Paginated events with visibility filtering
- `getEventById` - Single event with attendees
- `getUserEvents` - User's events with RSVP status
- `getUpcomingEvents` - Next 30 days

**Mutations**:
- `createEvent` - Manager/admin only
- `updateEvent` - Organizer or admin
- `deleteEvent` - Organizer or admin
- `updateRsvpStatus` - Employee updates own RSVP
- `inviteAttendees` - Bulk attendee invitation

### Task Operations (`src/lib/graphql/tasks-operations.ts`)

**Enhanced Features**:
- Department task filtering via `assignedToDepartmentId`
- Employee task filtering via `assigneeId`
- Combined employee + department task queries
- Mutually exclusive assignment validation

### Activity Log Operations (`src/lib/graphql/activity-logs-operations.ts`)

**Queries**:
- `getUserActivities` - Employee own activities (RLS-filtered)
- `getAuditLogs` - Admin system-wide audit (RLS-enforced)
- `getResourceActivityHistory` - Activity trail for specific resource
- `getActivitiesByDateRange` - Date range filtering

**No Mutations**: Activity logs are immutable (logged via database triggers)

### Notification Operations (`src/lib/graphql/notifications-operations.ts`)

**Queries**:
- `getUserNotifications` - User notifications with filtering
- `getUnreadCount` - Unread badge count
- `getNotificationById` - Single notification

**Mutations**:
- `markNotificationRead` - Mark single as read
- `markAllRead` - Clear notification bell
- `deleteNotification` - Remove notification

## 🔒 Security & Authorization

### Role Levels

- **Admin** (100) - Full system access
- **HR Manager** (80) - HR-specific permissions
- **Manager** (60) - Department management
- **Employee** (20) - Basic access

### Feature Permissions

- **Event Creation**: Manager or higher (level ≥ 60)
- **Task Creation**: Manager or higher (level ≥ 60)
- **Department Tasks**: Manager-only access (level ≥ 60)
- **Audit Logs**: Admin-only access (level 100)
- **Event Editing**: Event organizer or admin
- **Task Status Updates**: Task assignee or department member

### Row-Level Security (RLS)

All data access is filtered at the database level:
- **Events**: Users see only events matching their visibility level
- **Tasks**: Employees see only their assigned tasks or department tasks
- **Activities**: Employees see only their own activities; admins see all
- **Notifications**: Users see only notifications sent to them

## 📚 Best Practices

### Component Usage

1. **Always use server-side data loading** - Never call GraphQL operations from client components
2. **Use TypeScript strict mode** - All components have proper type definitions
3. **Follow Svelte 5 runes syntax** - Use `$state`, `$derived`, `$props` instead of stores
4. **Handle loading and error states** - All async operations should show loading states
5. **Accessibility first** - All components have ARIA labels and keyboard navigation
6. **Mobile responsive** - All components work on mobile devices

### Integration Example

Complete page integration example:

```svelte
<!-- +page.server.ts -->
<script lang="ts">
  import type { PageServerLoad } from './$types';
  import { EventsOperations } from '$lib/graphql/events-operations';

  export const load: PageServerLoad = async ({ locals, cookies }) => {
    if (!locals.user) {
      throw redirect(303, '/login');
    }

    const token = cookies.get('hr_token');
    const eventsOps = new EventsOperations();

    const events = await eventsOps.getAllEvents({
      first: 20,
      visibilityType: 'company'
    }, { token });

    return {
      user: locals.user,
      events: events.events
    };
  };
</script>

<!-- +page.svelte -->
<script lang="ts">
  import EventCard from '$lib/components/events/EventCard.svelte';
  import { goto } from '$app/navigation';

  let { data } = $props();

  function handleEventClick(event) {
    goto(`/dashboard/events/${event.id}`);
  }
</script>

<div class="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
  {#each data.events as event}
    <EventCard
      {event}
      userId={data.user.id}
      onClick={handleEventClick}
    />
  {/each}
</div>
```
